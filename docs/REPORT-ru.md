# DormFlow — отчёт по проекту

**Портал для студенческого общежития.** Студенты подают заявки на ремонт и
бронируют общие помещения, администратор обрабатывает заявки и публикует
объявления. Выбрал тему из-за двух рабочих процессов: заявка проходит через
статусы, а бронь не должна накладываться на чужую. Обе проверки на сервере.

📷 **СКРИНШОТ 1** → `01-landing.png` — главная страница.

## 1. Фронтенд

Восемь обычных HTML-страниц в `public/`, Express отдаёт их строкой
`app.use(express.static("public"))`. У каждой страницы свой скрипт плюс общий
`auth.js`. Фреймворк не использовал: в задании нужны HTML, CSS и JavaScript, и
так я понимаю каждую строку своего кода. Стили в одном файле, цвета в
CSS-переменных, вёрстка mobile-first с одним медиазапросом на 640px.

JavaScript хранит токен в `localStorage` и добавляет его заголовком к каждому
запросу; при `401` отправляет на вход. Списки строит через `textContent`, а не
`innerHTML`, чтобы текст студента показывался как текст и не выполнялся как код.

## 2. База данных

MongoDB и Mongoose, пять моделей:

| Модель | Поля |
|---|---|
| `User` | имя, email (уникальный), хеш пароля, комната, роль |
| `MaintenanceRequest` | автор → User, комната, категория, описание, приоритет, статус, история статусов |
| `Facility` | название, место, вместимость, длина слота, цена слота |
| `Booking` | пользователь → User, помещение → Facility, начало, конец, статус |
| `Announcement` | заголовок, текст, категория, автор → User |

Даты создания добавляются сами, для полей с готовым набором значений — `enum`.

Важные решения:
- **Пароль не хранится**, только bcrypt-хеш с `select: false` — обычные запросы
  его не загружают, поэтому он не попадёт в ответ.
- **Автор заявки — ссылка на пользователя**, а не имя строкой: по имени нельзя
  проверить, чья это заявка.
- **История статусов** — массив внутри самой заявки.
- **Время брони — настоящие `Date`**: строки неудобно сравнивать и на них
  ломаются часовые пояса.
- **Индексы** для списка админа, «моих заявок» и «моих броней»: без индекса база
  читает всю коллекцию.

## 3. Сервер

Код разделён на `routes` (адрес → функция), `middleware` (проверки),
`controllers` (логика и база) и `models`. Три middleware: `auth.js` проверяет
токен (нет → `401`), `requireAdmin.js` роль (не админ → `403`),
`errorHandler.js` превращает ошибки в нужные коды.

**Права доступа** сделаны в запросе к базе, а не скрытием кнопок:
```js
const filter = req.user.role === "admin" ? {} : { resident: req.user._id };
```
Фильтры поиска добавляются к этому же объекту, поэтому чужую заявку нельзя
открыть даже прямым запросом к API.

**Статусы** меняются только адресом `PATCH /api/requests/:id/status` по таблице:
```
Submitted   → Reviewed, Rejected, Cancelled
Reviewed    → In Progress, Rejected
In Progress → Completed
Completed, Rejected, Cancelled → дальше никуда
```
Переход не из таблицы → `409`. Каждое изменение дописывает запись в историю
через `$push`: эта операция только добавляет, старые записи не теряются.

**Бронирование.** Брони пересекаются, если новая начинается раньше конца старой
и заканчивается позже её начала. Проверки в коде мало — два запроса могут пройти
её одновременно, поэтому главная защита это уникальный индекс в базе на
помещение и время начала. Он учитывает только активные брони, поэтому после
отмены слот снова свободен.

**API — 23 адреса:** `/api/auth` (3), `/api/requests` (6), `/api/facilities` (5),
`/api/bookings` (4), `/api/announcements` (5). Список заявок принимает фильтры и
поиск. Коды: `200`, `201`, `400`, `401`, `403`, `404`, `409`.

## 4. Docker и запуск

```dockerfile
FROM node:20-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci --omit=dev
COPY . .
EXPOSE 3000
USER node
CMD ["node", "server.js"]
```

Сначала копирую `package.json`, потом код: Docker запоминает слои, и пакеты
переустанавливаются только при смене зависимостей. `.dockerignore` не пускает в
образ `.env`, чтобы секреты не лежали внутри.

```bash
npm install
cp .env.example .env      # вписать MONGODB_URI и JWT_SECRET
npm run seed              # демо-данные
npm start                 # http://localhost:3000
```
Через Docker: `docker build -t dormflow .`, затем
`docker run -p 3000:3000 --env-file .env dormflow`.

## Проверка и ограничения

Проверял вручную через `curl` и PowerShell: без токена → `401`, студент на
админском адресе → `403`, неверный переход → `409`, повторная бронь → `409`.

Ограничения: проект учебный; автотестов нет; Dockerfile написал, но сборку не
проверял; токен живёт семь дней и не отзывается; оплата не сделана.
